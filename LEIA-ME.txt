SERVNET — VERSÃO DE TESTE COM SUPABASE

CONFIGURAÇÃO
1. Crie um projeto Supabase.
2. Copie .env.example para .env e preencha a URL e a publishable key do projeto.
3. Execute supabase/migrations/20261028000000_servnet.sql no SQL Editor.
4. Desative novos cadastros públicos em Authentication settings.
5. Crie a conta TI/CPD em Authentication > Users; depois ajuste app_metadata com supabase/bootstrap-admin.sql.
6. Use npx supabase login, npx supabase link --project-ref REF_DO_PROJETO e npx supabase functions deploy member-management.
7. A função aceita localhost:5173 para teste. Para publicar o site, configure SERVNET_ALLOWED_ORIGINS com a origem oficial usando npx supabase secrets set.
8. Rode npm install e npm run dev.

O associado entra com matrícula e senha. A TI/CPD usa o e-mail da conta administrativa.

SEGURANÇA
- O navegador usa apenas a publishable key, sempre protegida pelas políticas RLS.
- A chave service role fica somente nas Edge Functions; nunca coloque essa chave no .env do frontend nem no GitHub.
- Não coloque nomes, matrículas reais nem arquivos .env neste repositório público.
- Para produção, habilite MFA para a equipe e configure backup e restauração do banco.
